What is an AI Harness?

Moving beyond naive "LLM wrappers": How to architect deterministic, reliable engineering systems around probabilistic models.

Architectural Maxim: Concepts > Code
An LLM is just a non-deterministic, probabilistic token predictor. It cannot manage state, cannot guarantee schemas, has no memory across sessions, and cannot adhere to boundaries on its own. The HARNESS is the deterministic machine you build around the model to enforce invariants.

1. Naive Wrapper vs. Real AI Harness

Attribute Naive LLM Wrapper Engineering AI Harness
Execution Model Direct API call (Prompt in → Text out) Deterministic State Machine & Event Loop
Context Control Dumps entire chat history into context window Selective Grounding via Vector RAG & Mastery Ledger
Reliability Hopes model produces valid text/JSON Strict validation, schema assertion & retry circuit breakers
Boundaries Unrestricted; easily spams or wanders Strict Notification Budget (2 touches/day), zero-nag backoff
Architecture Spaghetti code tied to OpenAI/Gemini SDKs Hexagonal Architecture: Domain decoupled from LLM & WhatsApp

2. Anatomy of our Go Learning Assistant Harness

1. Trigger & Scheduler

A lightweight background Go daemon running time.Ticker / cron jobs. Fires precisely twice daily (Morning Catalyst & Evening Review). It is the catalyst that wakes up the system.

2. Attention Arbitrator

Eliminates decision fatigue. Inspects all active Learning Paths, correlates user energy heuristics, and selects The ONE Most Important Thing for the day.

3. Context Assembly Engine

Queries SQLite vector store for relevant chunks of the active book (e.g. RDD), injects known misconceptions from the Mastery Ledger, and bounds token limits.

4. Deterministic Validator

Intercepts LLM response. Asserts that the drill contains exactly 1 question, is bite-sized (< 200 words), and contains no hallucinations or patronizing fluff.

5. Outbound WhatsApp Adapter

Sends the verified drill through whatsmeow. Logs the touchpoint in the audit database. Silences future proactive attempts until the next scheduled window.

6. Inbound Evaluator & Ledger

When you text back, the harness intercepts your answer, evaluates conceptual depth against the source text, and updates your spaced repetition score.

3. The Proactive Lifecycle (Morning Touchpoint)

Here is what happens under the hood when you receive an 8:00 AM WhatsApp message:

1. Cron Scheduler Trigger (8:00 AM)
The Go daemon initiates a morning touchpoint evaluation for user usr_123. Checks that the daily notification budget has not been exhausted.
2. Telemetry & Calendar Inspection
Checks Google Calendar for meeting density. If the day is packed with 7 hours of meetings, cognitive capacity is marked as LOW; if light, HIGH.
3. Attention Arbitration & Context Retrieval
Selects Software Design via RDD. Queries SQLite for vector chunks on "Stereotype Roles" and pulls previous misconceptions from the Mastery Ledger.
4. Probabilistic Generation via LLMPort
Prompts the Gemini adapter with grounded source text to produce a single, targeted micro-drill.
5. Invariant Validation & WhatsApp Delivery
Validates output length & format. Dispatches to WhatsApp via whatsmeow. State machine enters AWAITING_RESPONSE.

4. Hexagonal Architecture in Go

A true harness adheres strictly to the Dependency Inversion Principle. Notice how the core domain knows nothing about WhatsApp, Gemini, or SQLite:

// internal/core/ports/ports.go
package ports

import "context"

// Driving Port: How external triggers interact with our coach
type LearningCoachService interface {
    TriggerMorningKickoff(ctx context.Context, userID string) error
    ProcessInboundAnswer(ctx context.Context, userID, message string) (*EvaluationResult, error)
}

// Driven Port: WhatsApp output abstraction
type MessagingPort interface {
    SendText(ctx context.Context, toPhoneNumber, text string) error
}

// Driven Port: LLM generation abstraction
type LLMPort interface {
    EmbedText(ctx context.Context, text string) ([]float32, error)
    GenerateMicroDrill(ctx context.Context, chunk string, ledger MasteryLedger) (*Drill, error)
    EvaluateAnswer(ctx context.Context, expected, actual string) (*Score, error)
}

// Driven Port: Persistence abstraction
type RepositoryPort interface {
    GetActivePaths(ctx context.Context, userID string) ([]LearningPath, error)
    FindSimilarChunks(ctx context.Context, pathID string, embedding []float32, topK int) ([]Chunk, error)
    UpdateMasteryScore(ctx context.Context, userID, conceptID string, score float64) error
}

5. Key Takeaways for Building Your Harness

The Three Golden Rules of Harness Engineering
  1. Never trust model output directly: Always validate schemas, lengths, and invariants in deterministic code before showing it to the user.
  2. Keep state out of prompts: Store user progress, misconceptions, and spaced-repetition schedules in SQLite, not in massive prompt chat histories.
  3. Decouple I/O with Ports: If WhatsApp bans a test number or Gemini changes their API, you should only touch one adapter file—never your domain logic.
